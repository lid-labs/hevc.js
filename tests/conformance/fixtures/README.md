## Open-GOP bitstreams (CRA + RASL)

| File | Size | Resolution | Coded | Output | Type | MD5 (YUV decode) |
|------|------|------------|-------|--------|------|------------------|
| `opengop_qcif_12f.265` | 4.9K | 176x144 | 12 | 12 | IDR + 2x(CRA + 3 RASL) + trailing | `06e53846ff51cf35cadc97a080147e82` |
| `opengop_qcif_cra_first.265` | 1.9K | 176x144 | 7 | **4** | CRA + 3 RASL + 3 trailing | `9c249fb00174f2f6e6fbb3457c10679b` |
| `opengop_qcif_eos.265` | 4.9K | 176x144 | 12 | **7** | as `opengop_qcif_12f`, EOS before the second CRA | `47416569a3f352b681855d50a3895490` |

These two cover the §8.1 override on `PicOutputFlag`: a RASL picture whose associated
IRAP has `NoRaslOutputFlag = 1` is decoded but never output, because the references it
needs precede that IRAP in decode order and were never decoded.

The pair is what makes the clause testable in both directions:

- `opengop_qcif_12f.265` has its CRA **mid-stream**, where `NoRaslOutputFlag` is 0. Its
  RASL pictures are decodable and are output — 12 coded, 12 out. A decoder that applied
  the override too widely would drop six of them.
- `opengop_qcif_cra_first.265` is that same stream cut at its second CRA, so the CRA
  **opens** the bitstream and takes `NoRaslOutputFlag = 1`. Its three RASL pictures must
  not be output — 7 coded, 4 out.

`opengop_qcif_eos.265` is the uncut stream with an end-of-sequence NAL inserted before its
second CRA, the third case §8.1 gives `NoRaslOutputFlag = 1`. Two rules remove pictures:
that CRA's three RASL pictures are not output, and §C.5.2.2 empties the two pictures of the
first sequence still pending output (POC 3 and 4) without output, since the flag
`NoOutputOfPriorPicsFlag` is 1 on such a CRA. ffmpeg applies both — 12 coded, 7 out.

The cut is necessary: x265 only ever emits a CRA mid-stream. It keeps the parameter sets
from the top of the original stream, since the result starts at a picture.

All three are generated by `tools/gen_open_gop_fixtures.sh`, which prints the MD5s above.
Encoding: `x265 --preset medium --qp 22 --no-wpp --no-info --keyint 4 --min-keyint 4
--open-gop --bframes 3`. Deblocking and SAO are on, as the preset leaves them.

## Coding tool bitstreams (transform skip, scaling lists)

| File | Size | Resolution | Frames | Tool | MD5 (YUV decode) |
|------|------|------------|--------|------|------------------|
| `tskip_qcif_6f.265` | 4.2K | 176x144 | 6 | transform skip (`--tskip`) | `5ad310626adaab5f06237b5b2a0d5834` |
| `scaling_list_qcif_6f.265` | 3.9K | 176x144 | 6 | scaling lists in the SPS | `96cd30a17f4dab096e324d3cfd93f5c7` |

No other fixture uses either tool (#300). The scaling lists are asymmetric — each value
grows three times faster along x than along y — so the hash only matches a decoder that
places the coefficients through the diagonal scan of §7.4.5. Both fail on a decoder
without the matching fix.

Generated by `tools/gen_coding_tool_fixtures.sh`, which prints the MD5s above, from
ffmpeg's `testsrc2` pattern. Encoding: `x265 --preset medium --keyint 6 --bframes 2
--no-wpp --no-info`, plus `--tskip` or `--scaling-list <file>`.

## Merge candidate pruning bitstream

| File | Size | Resolution | Frames | Type | MD5 (YUV decode) |
|------|------|------------|--------|------|------------------|
| `merge_8x4_480p_16f.265` | 95K | 832x480 | 16 | I+P+B | `6485fca72247e3bb0c2e2fca487e9690` |

Its B pictures prune merge candidates (§8.5.3.2.3) next to 8x4 and 4x8 prediction
units, whose bi-prediction §8.5.3.2.2 turns into uni-prediction. A decoder that
compares the unused L1 motion vector when pruning keeps a duplicate candidate (#302):
8 of the 16 pictures then mismatch.

Generated by `tools/gen_merge_fixture.sh`, which prints the MD5 above, from Big Buck
Bunny (`demo/bbb720_singleslice.265`) scaled to 832x480. Encoding: `x265 --preset
slower --rect --min-cu-size 8 --max-merge 5 --b-adapt 0 --bframes 4 --qp 24 --no-wpp
--no-info`, x265 4.3. Few encodes hit the case; the encoded stream depends on the x265
and ffmpeg versions, so regenerating may give a stream that no longer does.

Bitstreams of the HEVC v1 conformance suite, unmodified apart from the extension
(`.bit` upstream), from
https://www.itu.int/wftp3/av-arch/jctvc-site/bitstream_exchange/draft_conformance/HEVC_v1/.
The MD5 is the one shipped with each stream, computed on the HM reference decoder output.

All four `SLIST` streams also enable transform skip. None matched its reference MD5
before #301 (transform skip shift, scaling list coefficient order); with #301 and #306
(merge candidate pruning) all four do, #300. `SLIST_D_Sony_9.265` is `str.bin` upstream.

The slices of an `RPLM_B` picture have different reference picture lists, which §8.3.4
builds per slice. It fails on a decoder that builds them once per picture, from the
first slice (#299), and also on one that applies those per-slice lists only during
slice decoding but not to TMVP or to the deblocking filter's Bs derivation.

## Common encoding parameters

```
x265 --preset medium/slow --qp 22 --no-wpp --no-info
```

- Chroma: 4:2:0
- Bit depth: 8-bit
- Profile: Main
- No WPP (single-thread CABAC)
- No info SEI (cleaner bitstream)

## How to regenerate the references

```bash
# Decode with ffmpeg
ffmpeg -y -i fixture.265 -pix_fmt yuv420p fixture_ref.yuv

# Compute the MD5
md5 -q fixture_ref.yuv  # macOS
md5sum fixture_ref.yuv   # Linux
```

## How to use in tests

```cpp
// The oracle test decodes the bitstream and compares the MD5 of the output YUV
// with the reference MD5 above
TEST(Oracle, I_64x64_QP22) {
    auto output = decode_file("tests/conformance/fixtures/i_64x64_qp22.265");
    EXPECT_EQ(md5(output), "48c64cd2de381113913149e92065d66c");
}
```
